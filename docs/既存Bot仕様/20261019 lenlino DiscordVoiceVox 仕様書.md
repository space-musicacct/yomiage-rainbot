## 2. 前提

本書は、びすこーど！で主に利用されている読み上げ Bot「ずんだもんβ」の公開実装 [lenlino/DiscordVoiceVox](https://github.com/lenlino/DiscordVoiceVox) (MIT License) の仕様を、ソースコードから網羅的に整理するものである。

要件定義で、読み上げれいんぼっとに取り込む機能・取り込まない機能を判断する材料とする。既存 Bot の全機能互換は前提としない (企画書 6.2)。本書に記載された機能は既存 Bot の動作であり、読み上げれいんぼっとの要件ではない。

## 3. システム構成

### 3.1 構成要素

| 構成要素 | 用途 | 備考 |
| --- | --- | --- |
| Bot 本体 | Discord との接続、コマンド、読み上げ | Python / py-cord。`AutoShardedBot` を継承した `FastShardedBot` |
| PostgreSQL | ユーザー設定・サーバー設定 (12.1) | asyncpg。プール最大 20 接続、`statement_timeout` 10 秒 |
| ファイル | 辞書、自動接続・アラーム設定、音声辞書の WAV など (12.2) | Bot と同じディレクトリ配下 (辞書は `DICT_LOC`) |
| 音声合成エンジン | 音声の生成 (3.2) | VOICEVOX ほか 5 種。HTTP API |
| Lavalink | VC への音声の送出 | lavalink.py。ノードが落ちると、再生中のプレイヤーを別ノードへ移す (7.3) |
| Stripe | プレミアムの紐付け、API トークンの発行 | `/activate` で使用。API キーが未設定だと、読み上げのプレミアム判定も変わる (11.1) |
| プレミアム一覧の URL (`CHECK_PREMIUM_ID`) | プレミアム利用者の一覧を 10 分ごとに取得 | 応答は `{金額: [ユーザー ID, ...]}` の JSON |
| 接続数の URL (`CHECK_STATS_COUNT_ID`) | 別の Bot の接続数を取得 | 設定されている場合のみ |
| 地震情報 WebSocket (`EEW_WEBHOOK_URL`) | 緊急地震速報の受信 | 設定されている場合のみ |
| translators | 翻訳 | プレミアム機能 (5.3) |

Discord の Intents は `guilds`、`guild_messages`、`message_content`、`voice_states` のみを有効にしている (L73-77)。メンバーのキャッシュは Intents から決まる範囲のみで、起動時のメンバー一括取得はしない。

### 3.2 音声合成エンジンと音声 ID

起動時に各エンジンの `/speakers` から話者一覧を取得し、エンジンごとに決まった値を ID に足して 1 つの一覧にまとめる (L600-698)。VOICEVOX 以外のエンジンは、接続できなければ一覧から外れる。

| 音声 ID | エンジン | 一覧の表示名 | 接続先の環境変数 | 無料で選べるか |
| --- | --- | --- | --- | --- |
| 0〜999 | VOICEVOX | `VOICEVOX:<話者名>` | `VOICEVOX_HOSTS` (複数を順番に使う) | 可 |
| 1000〜1999 | COEIROINK | `COEIROINK:<話者名>` | `COEIROINK_HOST` | 不可 |
| 2000〜2999 | SHAREVOX | `SHAREVOX:<話者名>` | `SHAREVOX_HOST` | 可 |
| 3000〜3999 | A.I.VOICE | `A.I.VOICE:<話者名>` | `AIVOICE_HOST` | 可 |
| 4000〜4999 | AquesTalk | `AquesTalk:<話者名>` | `AQUES_HOST` | 不可 |
| 5000〜5999 | Aivis | `Aivis:<話者名>` | `AIVIS_HOST` | 不可 |
| 6000 以上 | COEIROINK (ID から 1000 を引いて送る) | 一覧には現れない | `COEIROINK_HOST` | 不可 |

- 話者一覧は `VOICEVOX_HOST` (単数) から取得し、合成は `VOICEVOX_HOSTS` の各ホストを順番に使う (L2803-2809)
- 選択肢の文字列は `<話者名>(<スタイル名>) id:<ID>` の形式である (L694-696)
- 「無料で選べるか」が不可の声は、プレミアム利用者本人でなければ設定できない (L2091、L1241、L767)
- 声を設定したとき、次の注意書きを表示する (L2125-2130)
  - A.I.VOICE: 録音・配信での利用はできない
  - AquesTalk: 録音した音声を商用利用する場合は使用ライセンスが必要
  - VOICEVOX で、下記の無料リストにない声 (プレミアムでない場合): 無料プランでは混雑時にずんだもんに切り替わる (6.3)
- 無料リスト (`free_voice_list`) は次の 23 個の ID である (L2815)
  - `3, 1, 42, 8, 5, 14, 2, 76, 10, 7, 75, 22, 0, 58, 60, 45, 47, 4, 46, 61, 54, 66, 38`
- Aivis は、36 文字のモデル UUID を `/setvc` または `/set voice` の値に指定すると、`AIVIS_HOST` の `/register` に登録し、話者一覧を作り直す (L2170-2184)

### 3.4 シャーディングとクラスタ

- `CLUSTER_COUNT` が 2 以上のとき、シャード ID を `CLUSTER_COUNT` で割った余りでクラスタに振り分け、各プロセスは自分の担当シャードだけを起動する (`fast_sharded_bot.py`)
- シャードは Discord の `max_concurrency` の数ずつ、5 秒おきに起動する
- スラッシュコマンドの登録 (同期) はクラスタ 0 だけが行う (L193-198)
- 各クラスタは 1 分ごとに、導入サーバー数と接続数を DB (`cluster_stats`) に書き、120 秒以内に更新された全クラスタの合計をステータス表示と混雑判定に使う (L3940-3975)
- `/stop` を受けたクラスタは共有ディレクトリに停止シグナル (`stop_signal.json`) を書き、他のクラスタはファイルの変更を検知して停止する。起動より前に書かれたシグナルは無視する (`cluster_signal.py`、L4154-4175)
- 単一サーバーでの利用には関係しないが、既存 Bot の構成として記載する

- 「既定の権限」は、Discord 側でコマンドを表示・実行できるメンバーの初期値 (`default_member_permissions`) である。サーバーの管理者が Discord の連携設定で変更できる

- コマンドの実行中に例外が起きると、実行者だけに「コマンドの実行中にエラーが発生しました。… uuid: <UUID>」を返し、同じ UUID をログに残す (L3087-3100)

### 4.2 コマンド詳細

#### C-001 `/vc`

| 項目 | 内容 |
| --- | --- |
| 引数 | なし |
| 処理 (切断) | Bot がそのサーバーで接続中で、読み上げ対象チャンネルが記録されていれば切断する。実行者がどの VC にいても切断する |
| 処理 (接続) | 実行者の VC に接続し、コマンドを実行したテキストチャンネルを読み上げ対象チャンネルとして記録する。すでに音声接続が残っていれば強制切断し、2 秒待ってから接続する |
| 接続前の確認 | VC の人数上限、Bot の接続権限、Bot のタイムアウト、`USAGE_LIMIT_PRICE` のプラン |
| プレミアム | 実行者、またはサーバーの `premium_user` がプレミアムなら、サーバーをプレミアムサーバーにする (11.1) |
| 応答 | 接続時は「Connect」と tips (14 種からランダム)。プレミアムなら「Premium <金額>」を付ける。切断時は「Disconnect」。サーバー設定 `joinnotice` が off なら、応答をすぐに削除する |
| エラー | 実行者が VC にいない、満員、接続権限がない、タイムアウト中、必要なプランがない、接続に失敗 (「現在起動中です。」) |
| 該当箇所 | L949-1048 |

#### C-003 `/setvc`

| 項目 | 内容 |
| --- | --- |
| 引数 | `voiceid` (任意、補完あり)、`speed` (任意、整数)、`pitch` (任意、整数)、`target_user` (任意、メンバー) |
| 処理 (自分) | すべて省略すると、現在の設定を表示して声の選択 UI (4.3) を出す。`speed` / `pitch` だけを指定すると、声は現在の設定のまま検証し直す |
| `voiceid` の形式 | 数字、補完候補の文字列 (`... id:<ID>` の ID 部分を使う)、または Aivis のモデル UUID (3.2) |
| 検証 (自分) | 存在しない ID はエラー。プレミアム限定の声はプレミアム利用者本人のみ。`speed` は 50 以上 (上限なし)。`pitch` は範囲を確認しない |
| 処理 (`target_user`) | 実行者に `manage_messages` 権限が必要。そのサーバーの中だけで、対象メンバーの声・速度・ピッチを上書きする (`guild.member_voices`)。`voiceid` に `off` で上書きを解除する |
| 検証 (`target_user`) | `voiceid` / `speed` / `pitch` のいずれかが必要。プレミアム限定の声は、対象メンバーがプレミアム利用者の場合のみ。`speed` は 50 以上、`pitch` は -100〜100 に丸める |
| 補完 | 未入力時は先頭に「現在の設定」を出す (`target_user` 指定時は出さない)。`speed` / `pitch` は現在値と既定値 (100 / 0) を出す。候補は最大 25 件 |
| 応答 | 変更後の声と、3.2 の注意書き。速度・ピッチを変えた場合はその旨を追記する |
| 該当箇所 | L1896-2168 |

## 5. 読み上げ

### 5.1 読み上げる条件

メッセージを受け取ったとき (`on_message`)、次をすべて満たせば読み上げキューに入れる (L3063-3085)。

- そのサーバーで Bot が VC に接続している
- メッセージのチャンネルが、読み上げ対象チャンネル、または接続中の VC のテキストチャット
- 本文が `!` または `！` で始まらない

送信者が Bot かどうかは確認していない。メッセージの編集・削除は扱わない。

キューに入れる文字列は次のように組み立てる。

| 対象 | 組み立て |
| --- | --- |
| 添付ファイルがある | 本文の先頭に「テンプファイル」を付ける (`!` の判定の後) |
| スタンプがある | スタンプの名前を本文の末尾に付ける (区切りなし) |
| 転送されたメッセージ (サーバー設定 `readforward` が on) | 「<本文> テンソウ <転送元の本文>」。本文が空なら「転送 <転送元の本文>」。転送元の添付・スタンプも同じように組み立てる |

### 5.2 読み上げキュー

- サーバーごとに 1 本の先入れ先出しのキューで、1 件ずつ処理する
- 直前の 2 件と同じ文字列は捨てる (同じ文字列が 3 回以上続くと、3 回目以降を読まない)
- 1 件の処理は再生を始めた時点で終わり、次の件の処理に移る。次の件は前の再生が終わるのを待つ (7.3)
- キューが空になって 10 秒たつと、「直前の発言者」(5.3 の名前の省略) と「直前の 2 件」をリセットする
- 本文がちょうど `zundamon!!stop` のメッセージが処理の順番になると、そのサーバーのキューを捨てる (14 章 N-010)
- 該当箇所: L3102-3133、L3150-3153、L3473-3483

### 5.3 1 件の読み上げの処理順

キューの先頭の 1 件を次の順に処理する (L3136-3483)。

1. 送信者が `/mute` でミュートされていれば読まない
2. 改行を消す。空になれば読まない
3. サーバー設定 `readname` が on なら、表示名を先頭に付ける (`readsan` が on なら「さん」付き)。`skip_repeat_name` が on で、直前の発言者と同じなら付けない。入退室の読み上げには付けない。アラームと緊急地震速報は Bot 自身の発言として扱うため、付ける場合は Bot の表示名になる
4. 文字数の上限 + 50 文字で切る (8 章)
5. プレミアムサーバーなら、元の本文から `.v<数字>` (声)、`.p<数字>` (ピッチ)、`.s<数字>` (速度) を探す (6.1)
6. 声を決める (6.1)
7. URL を「ユーアールエル省略」に置き換える (言語が `ko` なら「유알엘생략」)
8. サーバー辞書、続いてグローバル辞書で置換する (9 章)。このとき文字列全体を NFKC 正規化・小文字化する
9. サーバー設定 `reademoji` が on なら、絵文字を emoji ライブラリで日本語の名前の文字列に変える
10. 次を消す: カスタム絵文字 `<:…>`、アニメーション絵文字 `<a…>`、`.v` / `.p` / `.s` の指定 (プレミアムサーバーでなくても消える)、スポイラー `||…||` (中身ごと)
11. コードブロック ` ```…``` ` を「コードブロック省略」に置き換える
12. メンション: プレミアムサーバーで `readmention` が on なら、ユーザーメンションを「メンション<表示名>」、ロールメンションを「メンション<ロール名>」に置き換える。それ以外は `<@…>` の形を消す。チャンネルメンション `<#…>` はどちらの場合も対象外
13. 空になれば読まない
14. プレミアムサーバーなら、音声辞書の区切りで分割する。区切りの中が保存済みの WAV ファイル名なら、その音声を使う (9.1)。それ以外の部分は 15 へ
15. 言語ごとの処理 (サーバー設定 `lang`)
    - `ja`: サーバーが 300 円以上のプレミアムで `translate` が on、かつ先頭の 1 文字がひらがな・カタカナ・漢字でなければ、日本語に翻訳する → 英字を含めば romajitable でカタカナにする → `w` が 4 つ以上続く部分を「ワラ」にし、`w` 以外の文字がなければ全体を「ワラ」にする → 上限で切って「以下略」を付ける (8 章)
    - `ko`: `w` が 4 つ以上続く部分を「ㅋ」にし、`w` 以外の文字がなければ全体を「ㅋ」にする → 50 文字 (プレミアムは 100 文字) で切って「이하 약어」を付ける → ko2kana で仮名にする → 空白を消す
    - 声が A.I.VOICE (3000〜3999) なら、最後の 1 つを除いて記号を消す
16. 速度・ピッチを決める (6.1、6.2)
17. 音声を合成する (7.1)。部分が複数あれば 1 つの音声に結合する
18. 再生する (7.3)

途中で失敗した場合 (合成の失敗、Lavalink の検索の失敗・5 秒のタイムアウト、例外など) は、ログに残してその 1 件を読まずに次へ進む。

ja の処理で、英字のカタカナ化は `w` の置き換えより先に行う。`w` が置き換えの時点で残っているかは romajitable の変換結果による (未確認)。

### 5.4 入退室の読み上げ

サーバー設定 `readjoinleave` が on のとき (L3775-3791)。

- Bot が接続中の VC に、Bot 自身以外のメンバーが入った・出たときに読む。同じ VC の中での状態の変化 (ミュート等) では読まない
- 名前は、表示名 → サーバー辞書 → グローバル辞書 → `<…>` の形と絵文字を消す → `readsan` が on なら「さん」を付ける
- 文は `join_text` / `leave_text` の `&name` を名前に置き換えたもの。既定は「&nameが入室したのだ、」「&nameが退出したのだ、」
- キューに入れたあとは 5.3 と同じ処理を通る (名前の読み上げは付けない)。入退室したメンバーが `/mute` されていれば読まない

### 5.5 自動接続

次をすべて満たすとき、Bot が VC に接続する (L3634-3739)。

- そのサーバーで Bot が接続していない
- Bot でないメンバーが VC に入り、その VC の人数が 1 人になった (または読み上げ対象チャンネルの記録が残っている)
- VC の人数上限、Bot の接続・発言権限、Bot のタイムアウトに引っかからない
- その VC が自動接続先 (10 章 `autojoin`) に登録されている
- `USAGE_LIMIT_PRICE` のプランを満たす

接続の動作は次のとおり。

- 1 秒待って、まだ接続していないことを確かめてから接続する
- VC と対になったテキストチャンネルを読み上げ対象チャンネルにする
- Bot に「メンバーのスピーカーをミュート」の権限があれば、自分のスピーカーをミュートする
- サーバー設定 `joinnotice` が on なら、読み上げ対象チャンネルに「Connect」と tips を送る
- プレミアムの判定は C-001 と同じ

### 5.6 自動切断

VC の状態が変わったときに、Bot が接続中の VC が Bot だけになっていれば切断する (L3793-3809)。

### 5.7 プレミアムモードへの切り替え

接続中の VC にプレミアム利用者が入ると、そのサーバーをプレミアムサーバーにし、読み上げ対象チャンネルに「プレミアムモードに切り替わりました。」を送る。利用者が VC から出ても、切断するまでプレミアムサーバーのままである (L3747-3773)。

### 5.8 再起動からの復帰

- 10 分ごとと停止時に、接続中のサーバー・VC・読み上げ対象チャンネル・プレミアムの状態をファイル (`bot_stop.json`) に保存する (L2476-2486)
- 起動時にファイルを読み、各読み上げ対象チャンネルに「復帰しました」を送り、VC に誰かいれば再接続する。10 秒後に Bot だけの VC からは切断する (L2489-2556)

## 6. 声・速度・ピッチの決まり方

### 6.1 優先順位

右にあるものほど優先する (L3206-3264、L3331-3340)。

| 項目 | 優先順位 (低 → 高) |
| --- | --- |
| 声 | 自分の設定 (既定 3) → サーバー内の上書き (`/setvc target_user`) → 本文の `.v<数字>` (プレミアムサーバーのみ) |
| 速度 | 自分の設定 (既定 100) → サーバー内の上書き → 本文の `.s<数字>` (50 以上に丸める) → キュー連動の速度アップ (6.2) |
| ピッチ | 自分の設定 (既定 0) → サーバー内の上書き → 本文の `.p<数字>` (-100〜100 に丸める) |

- 声が決まったあと、その声がサーバー設定 `mute-voice` に含まれていれば、声を 3 に変える
- 自分の設定は、初めて読み出すときに `voiceid` を 3 として行を作る。読み出しに失敗した場合 (DB のタイムアウトなど) の既定は 0 である (L3252、L2741-2757)

### 6.2 キュー連動の速度アップ

サーバー設定 `queue_speedup` が on (既定) で、キューに 5 件以上たまっているとき、速度を次の値にする (L3342-3349)。

`min(300, max(元の速度, 元の速度 + (キューの件数 − 4) × 20))`

### 6.3 設定と異なる声で読まれる条件

コード上、次の場合に、利用者が設定した声と異なる声で読む。企画書 3.2 の事象との関係は確認していない。

| 条件 | 読む声 | 該当箇所 |
| --- | --- | --- |
| 声がサーバー設定 `mute-voice` に含まれる | 3 | L3261-3263 |
| 声が VOICEVOX (0〜999) で、GPU サーバーを使う条件 (7.2) に当たらず、全クラスタ合計の接続数が 1500 以上 | 3 | L2864-2867 |
| 自分の設定の読み出しに失敗した (DB のタイムアウトなど) | 0 | L3252、L2755-2757 |
| プレミアムサーバーで、本文に `.v<数字>` がある | その数字の声 | L3211-3216 |
| `/setvc target_user` でサーバー内の上書きがある | 上書きの声 | L3242-3250 |
| サーバー内の上書き (`member_voices`) が辞書の形で読み出せない (企画書 P-001) | 上書きが効かず、自分の設定の声 | L3242-3247 |

## 7. 音声の合成と再生

### 7.1 合成の経路

読み上げる部分の数によって、合成する場所が変わる (L2782-3051、`LavalinkClient.py`)。

| 場合 | 合成する場所 | 流れ |
| --- | --- | --- |
| 部分が 1 つ (通常) | Lavalink ノード側 | Bot は `usegpu_<合成先>_<クエリ先>_<話者>_<本文>` の文字列を作り、`LavalinkClient.py` がこれを `_` で分割して `vv://voicevox?speaker=…&address=…&query-address=…&text=…&retry=…` に変換し、Lavalink に検索させる (企画書 P-007 の経路) |
| 部分が複数 (音声辞書を含む) | Bot 側 | クエリ先の `/audio_query` → (かなが長ければ 8 章の上限で切って `/accent_phrases`) → 合成先の `/synthesis` → 各 WAV を `VOICEVOX_HOST` の `/connect_waves` で 1 つにする → base64 で Lavalink に渡す |

- 合成時の速度・ピッチは常に 100・0 で、速度・ピッチは再生時に Lavalink の Timescale フィルターでかける。値は `speed = 速度 / 100`、`pitch = ピッチ / 100 + 1`
- 合成先: VOICEVOX は `VOICEVOX_HOSTS` を順番に使う。ほかのエンジンはそれぞれの接続先
- クエリ先: VOICEVOX と AquesTalk は `VOICEVOX_QUERY_HOST`、ほかのエンジンは合成先と同じ
- `/audio_query` の応答に `x-address` ヘッダがあれば、合成先をその値に変える
- A.I.VOICE は `/audio_query` の応答をそのまま音声として使う
- COEIROINK・SHAREVOX は音量を 0.8 倍にする
- Lavalink を使わない経路 (FFmpeg で直接再生) もコードにあるが、Lavalink の使用は固定で有効になっている (L59)

### 7.2 GPU サーバー

環境変数 `IS_GPU` が True のとき、VOICEVOX の声は次の場合に `GPU_HOST` で合成する (L2828-2837)。

- 声が無料リスト (3.2) にある
- プレミアムサーバーで、全クラスタ合計の接続数が 1500 以上
- プレミアムサーバーで、接続数が 800 以上、かつサーバーが 300 円以上のプレミアム
- プレミアムサーバーで、サーバーが 500 円以上のプレミアム

### 7.3 再生

- 再生の前に、そのサーバーのプレイヤーに Timescale フィルターをかける
- 前の音声が再生中なら 1 秒ごとに待つ。30 秒を超えたら VC に接続し直してから再生する (L3439-3470)
- Lavalink ノードが切断されたら、そのノードのプレイヤーを別の使えるノードへ移し、再生位置の 250 ミリ秒前から再開する (L442-516)

## 8. 文字数の上限

ここでいう「上限」は、サーバー設定 `text_limit` とプランの上限 (無料 50 文字、プレミアムサーバー 100 文字) の小さい方である。`text_limit` を省略した場合はプランの上限になる。

| 段階 | 無料 | プレミアムサーバー | 超えたとき | 該当箇所 |

## 11. プレミアムプラン

### 11.1 判定

- プレミアム利用者: `CHECK_PREMIUM_ID` の URL から 10 分ごとに `{金額: [ユーザー ID, ...]}` を取得し、一覧を作り直す。各利用者の `premium_guild1〜3` のサーバーも、同じ金額の対象として一覧に加える (L4066-4102、L3978-4002)
- サーバーの金額の判定: 一覧に含まれるか、接続時に記録した金額、またはサーバーの `premium_user` の金額で判定する (L4707-4740)
- プレミアムサーバー: 接続時 (C-001、5.5) に、接続した人かサーバーの `premium_user` がプレミアムならプレミアムサーバーにする。接続中にプレミアム利用者が VC に入った場合も同じ (5.7)。読み上げでのプレミアムの判定はこれで行う
- 環境変数 `STRIPE_TOKEN` が未設定なら、読み上げ時は全サーバーをプレミアムサーバーとして扱う (L3170-3171)
- `USAGE_LIMIT_PRICE` が 0 より大きければ、接続した人かサーバーの `premium_user` にその金額以上のプランがないと接続できない

## 13. 運用まわり

### 13.1 定期処理

| 間隔 | 処理 | 該当箇所 |
| --- | --- | --- |
| 1 分 | 接続していないサーバーを接続一覧から消す。100 円以上のプレミアムの接続中サーバーで、時刻と曜日が合うアラームを読み上げ、Embed を送る。ステータスに「<接続数>/<導入数>読み上げ中」と平均の生成時間 (無料 / プレミアム) を表示する。クラスタの集計を記録する | L3818-3918 |
| 10 分 | 接続リストを保存する (5.8) | L4061-4063 |
| 10 分 | プレミアム一覧を更新する (初回以外は 0〜600 秒ずらす) | L4066-4102 |
| 24 時間 | グローバル辞書の申請を判定する (9.2) | L4005-4058 |
| 毎週水曜 9:00 (JST) | 「定期再起動」の告知をして停止する (`/stop` と同じ)。プロセスの再起動は systemd または `run.sh` が行う | L4817-4822 |

### 13.2 緊急地震速報

`EEW_WEBHOOK_URL` の WebSocket から受け取った JSON の `code` が 556 のとき、対象の都道府県を並べた Embed (「緊急地震速報（警報）」) を、プレミアムサーバーのうち `eew` が on のサーバーの読み上げ対象チャンネルに送り、「緊急地震速報　<都道府県>」を読み上げる。`CHECK_STATS_COUNT_ID` が未設定なら、コードに直接書かれたチャンネルにも送る (L4743-4815)。

### 13.3 起動・停止

- 起動時: HTTP 接続、DB 接続とテーブルの用意、話者一覧の取得、定期処理の開始、Lavalink ノードの接続、地震情報 WebSocket の接続、エンジン辞書の同期 (9.3)、自動再接続 (5.8)、ファイル監視の開始 (L4178-4217)
- ファイル監視: `commands/` の `.py` が変わるとそのコグを読み込み直す。`main.py` が変わると停止する (L4110-4151)
- 停止・再起動: C-010、C-011

### 13.4 その他のイベント

| イベント | 処理 |
| --- | --- |
| サーバーへの参加 | 自分のニックネームを `BOT_NICKNAME` にする |
| サーバーからの退出 | そのサーバーの辞書キャッシュを消す |
| Discord との WebSocket の遅延 (「websocket is … behind」のログ) | 通知チャンネルに投稿する (5 分に 1 回まで) |

### 13.5 ログ

- 標準出力と、起動ごとのログファイル (12.2) に出す
- 読み上げに 3 秒以上かかったとき、処理段階ごとの時間を、声・速度・ピッチ・読み上げた文字列と一緒に出す (L3435-3437)
- 読み上げ中に例外が起きたとき、例外と読み上げようとした文字列・声の ID を出す (L3419-3421)
- 話者一覧の取得時に、一覧の全体を出す

### 13.6 デプロイとテスト

- GitHub Actions で、`master` への push 時に本番の各ディレクトリ (6 か所)、`dev` への push 時に開発用の 1 か所で `git pull` する。接続先は GitHub の Secrets
- systemd のテンプレート (`deploy/discordbot@.service`、`Restart=always`) と、終了したら起動し直す `run.sh` がある
- テストは `tests/test_shard_split.py` (シャードの振り分け) のみである。`cluster_signal.py` の説明に `tests/test_cluster_signal.py` が書かれているが、リポジトリにはない
