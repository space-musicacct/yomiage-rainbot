## 5. スコープ

### 5.1 開発対象

| 項目 | 内容 |
| --- | --- |
| 開発対象 | Discord の読み上げ Bot |
| 主な対象 | テキストチャンネルのメッセージと、VC の入退室の読み上げ。利用者ごとの声の設定、辞書、読み上げの管理 |
| 対象サーバー | `server_id.json` に設定したサーバー (複数設定できる) |

### 5.2 対象外

既存 Bot (ずんだもんβ) の機能のうち、本システムで扱わないものは以下のとおり。

| 項目 | 理由 |
| --- | --- |
| キュー連動の速度アップ | リソース消費上の懸念があるため、今回は見送る |
| アラーム | 読み上げ Bot に必ずしも必要な機能ではないため |
| 翻訳 | 読み上げ Bot に必ずしも必要な機能ではないため |
| 韓国語での読み上げ | 読み上げ Bot に必ずしも必要な機能ではないため |
| 本文中の指定 (`.v` / `.p` / `.s`) による声・ピッチ・速度の一時変更 | 読み上げ Bot に必ずしも必要な機能ではないため |
| 緊急地震速報 | 読み上げ Bot の責務の範囲を大幅に超えるため |
| プレミアムプラン (Stripe 連携、`/activate` を含む) | すべての導入サーバーに汎用的に読み上げを提供する用途ではなく、対象サーバーを限定して運用するため |
| シャーディング・クラスタ構成 | すべての導入サーバーに汎用的に読み上げを提供する用途ではなく、対象サーバーを限定して運用するため |
| 管理サーバー限定の運用コマンド (`/stop`、`/restart`、`/reload`) | 運用の操作はサーバーに SSH して行えばよいため。異常があった場合も、ログを確認できなければこれらのコマンドだけでは根本的な解決にならず、利点が少ない |
| GPU サーバーでの合成 | サーバー・開発用のノート PC のいずれも合成に使える GPU を持たず (ノート PC は CPU 内蔵のグラフィックのみ)、検証する手段がないため |
| ステータス表示 (接続数・生成時間) | すべての導入サーバーに汎用的に読み上げを提供する用途ではなく、対象サーバーを限定して運用するため |
| 混雑時の声の切り替え (全体の接続数が多いと、VOICEVOX の声を ID 3 に切り替える) | すべての導入サーバーに汎用的に読み上げを提供する用途ではなく、対象サーバーを限定して運用するため |

## 6. 利用フロー

### 6.1 基本フロー

1. 利用者が VC に入る
2. 利用者が `/vc` を実行する。または、自動接続先の VC であれば Bot が自動で接続する
3. 利用者が、読み上げ対象のテキストチャンネル (または VC のテキストチャット) に発言する
4. Bot が、発言を読み上げる文に変換し、利用者の声・速度・ピッチで読み上げる
5. 利用者が `/vc` を実行する。または、VC が Bot だけになったら Bot が自動で切断する

### 6.2 利用シナリオ

| ID | シナリオ | 内容 |
| --- | --- | --- |
| U-001 | 聞き専の参加者の発言 | マイクを使わない参加者が、テキストで発言して VC の会話に加わる |
| U-002 | 自分の声の設定 | 利用者が `/setvc` で声・速度・ピッチを選ぶ。別の対象サーバーでも同じ設定を使う場合は、`/setvc-export` で出力し、そのサーバーで `/setvc-import` する |
| U-003 | 読み方の登録 | 利用者が、読み間違えられる単語を `/dict-add` で登録する |
| U-004 | 既存 Bot からの辞書の引き継ぎ | サーバー管理者が、既存 Bot の辞書の JSON を `/dict-import` で一括登録し、登録できなかった項目の一覧を確認する |
| U-005 | 迷惑な読み上げへの対処 | サーバー管理者が、`/skip-all` で読み上げを止め、`/mute-add` で特定のメンバーの発言を読み上げないようにする |
| U-006 | 定番の VC での自動接続 | サーバー管理者が `/server-set` で自動接続先を登録し、以降は最初の 1 人が VC に入ると Bot が接続する |
| U-007 | Bot の再起動 | 運用者が Bot を再起動する。Bot は停止前に通知を送り、起動後に、人がいる VC へ接続し直す |

### 7.2 機能詳細

#### F-001

| 項目 | 内容 |
| --- | --- |
| 機能名 | 対象サーバーの制限 |
| 目的 | Bot が動作するサーバーを、運用者が設定したサーバーに限る |
| 利用者 | 運用者 (設定)、一般利用者・サーバー管理者 (対象外のサーバーで利用しようとした場合) |
| 入力 | `server_id.json` (対象サーバーのサーバー ID の配列) |
| 処理 | 起動時に `server_id.json` を読み込む。内容の変更は、Bot の再起動で反映する。配列にないサーバーでは、メッセージの読み上げ・自動接続などの動作を行わない |
| 出力 | 配列にないサーバーでコマンドが実行された場合、そのサーバーでは利用できない旨のエラーを、実行者にのみ見える形で返す |
| 例外・エラー | 起動時に `server_id.json` が存在しない、または内容が不正な場合は、起動せずにログへエラーを出す |
| 備考 | `server_id.json` は Git の管理対象外とし、見本の `server_id.example.json` をリポジトリに含める |

#### F-002

| 項目 | 内容 |
| --- | --- |
| 機能名 | 読み上げの開始・終了 |
| 目的 | VC での読み上げを開始・終了する |
| 利用者 | 一般利用者 |
| 入力 | `/vc` (1 つのコマンドで開始と終了を切り替える) |
| 処理 | Bot がそのサーバーで接続していなければ、実行者のいる VC に接続し、コマンドを実行したテキストチャンネルを読み上げ対象として記録する。接続中で、実行者が Bot と同じ VC にいれば切断する |
| 出力 | 接続・切断の通知。通知を出すかどうかは、サーバー単位の読み上げ設定 (F-023) で選べる |
| 例外・エラー | 実行者が VC にいない。Bot の接続中に、Bot と別の VC にいる利用者が実行した (切断しない)。Bot に接続の権限がない、VC が満員などで接続できない |
| 備考 | 既存 Bot は、接続中に実行すると、実行者がどの VC にいても切断していた (既存 Bot 仕様書 N-011)。本システムでは、Bot と同じ VC にいる利用者のみ切断できる |

#### F-003

| 項目 | 内容 |
| --- | --- |
| 機能名 | メッセージの読み上げ |
| 目的 | テキストチャンネルの発言を、VC で読み上げる |
| 利用者 | 一般利用者 |
| 入力 | 読み上げ対象のテキストチャンネル、および Bot が接続中の VC のテキストチャットへの発言 |
| 処理 | 発言を読み上げキュー (F-004) に追加する。`!` / `！` で始まる発言は読まない。発言者が Bot の場合も読み上げる。ただし、本システム (読み上げれいんぼっと) 自身の発言は読まない |
| 出力 | VC での読み上げ |
| 例外・エラー | Bot がそのサーバーで接続していない場合は読まない |
| 備考 | メッセージの編集・削除は扱わない (既存 Bot と同じ)。読み上げる文への変換は F-009〜F-011 |

#### F-004

| 項目 | 内容 |
| --- | --- |
| 機能名 | 読み上げキュー |
| 目的 | 複数の読み上げを、順番に処理する |
| 利用者 | 一般利用者 |
| 入力 | 読み上げの追加 (メッセージ F-003、入退室 F-008) |
| 処理 | サーバーごとに 1 本のキューを持ち、追加された順に 1 件ずつ読み上げる。同じ文が続いても、すべて読む |
| 出力 | VC での読み上げ |
| 例外・エラー | キューの件数は 1 サーバーあたり 30 件までとし、30 件に達している間に追加された読み上げは捨てる |
| 備考 | 既存 Bot は、同じ文字列が 3 回以上続くと 3 回目以降を捨てていた。また、キューの件数に上限はなかった (既存 Bot 仕様書 5.2) |

#### F-005

| 項目 | 内容 |
| --- | --- |
| 機能名 | スキップ |
| 目的 | 読み上げを途中で止める |
| 利用者 | 一般利用者 (Bot と同じ VC にいる利用者) |
| 入力 | スキップの操作。止める範囲として、次の 2 つを選べる (コマンドの形は 8 章で定める) |
| 処理 | 今の 1 件のみ: 読み上げ中の 1 件を止めて、キューの次の件に進む。すべて: 読み上げ中の 1 件を止め、キューに残っている読み上げもすべて消す |
| 出力 | スキップした旨の応答 |
| 例外・エラー | 実行者が Bot と同じ VC にいない。読み上げ中でない場合は、その旨を返す |
| 備考 | 既存 Bot は「今の 1 件のみ」だけで、読み上げ中でなくてもスキップした旨を返していた (既存 Bot 仕様書 N-003) |

#### F-006

| 項目 | 内容 |
| --- | --- |
| 機能名 | 自動接続 |
| 目的 | コマンドを実行しなくても、登録した VC で読み上げを始める |
| 利用者 | サーバー管理者 (登録)、一般利用者 (利用) |
| 入力 | 自動接続先の登録 (VC と、読み上げ対象のテキストチャンネルの組)。登録はサーバー単位の読み上げ設定 (F-023) で行う |
| 処理 | Bot がそのサーバーで接続していないとき、登録した VC に Bot 以外のメンバーが入り、その VC の Bot を除いた人数が 1 人になったら接続する。登録時に組にしたテキストチャンネルを読み上げ対象として記録する。1 サーバーに複数の VC を登録できる |
| 出力 | 接続の通知 (通知を出すかどうかは F-002 と同じ設定に従う) |
| 例外・エラー | Bot に接続の権限がない、VC が満員などで接続できない場合は接続しない |
| 備考 | 既存 Bot は、Bot も含めた人数が 1 人になったときに接続していたため、ほかの Bot が VC にいると自動接続しなかった (既存 Bot 仕様書 5.5) |

#### F-007

| 項目 | 内容 |
| --- | --- |
| 機能名 | 自動切断 |
| 目的 | 聞く人がいなくなった VC から、自動で抜ける |
| 利用者 | — (自動で動作する) |
| 入力 | VC のメンバーの変化 |
| 処理 | Bot が接続中の VC が Bot だけになったら、すぐに切断する。Bot が別の VC に移動させられた場合は、移動先の VC で読み上げを続ける (読み上げ対象のテキストチャンネルは変えない) |
| 出力 | なし (切断の通知は出さない) |
| 例外・エラー | — |
| 備考 | 自動切断は既存 Bot と同じ動作 (既存 Bot 仕様書 5.6)。移動先の VC で続ける動作も既存 Bot と同じ (既存 Bot の `main.py` L360-377。既存 Bot 仕様書には記載していない) |

#### F-008

| 項目 | 内容 |
| --- | --- |
| 機能名 | 入退室の読み上げ |
| 目的 | Bot が接続中の VC に、誰が入った・出たかを知らせる |
| 利用者 | 一般利用者 |
| 入力 | Bot が接続中の VC へのメンバーの入室・退室 |
| 処理 | 入室・退室したメンバーの名前を入れた文を、読み上げキュー (F-004) に追加する。同じ VC の中での状態の変化 (ミュート等) では読まない。ほかの Bot の入退室も読み上げる。ただし、本システム自身の入退室は読まない |
| 出力 | VC での読み上げ |
| 例外・エラー | メンバーの読み上げミュート (F-020) の対象になっているメンバーの入退室は読まない |
| 備考 | 既定は off で、サーバー単位の読み上げ設定 (F-023) で on にする。読み上げる文は、入室・退室それぞれサーバーごとに変えられ、文中の `&name` を名前に置き換える。既定の文は Q-011。名前の読み方は F-009 に従う |

#### F-009

| 項目 | 内容 |
| --- | --- |
| 機能名 | 名前の読み上げ |
| 目的 | 誰の発言かを、読み上げで分かるようにする |

## 8. コマンド要件

### 8.1 方針

利用者は PC だけでなく、スマートフォン等からも操作する。直感的に分かるように、1 つのコマンドに複数の操作を持たせず (サブコマンドや、操作を選ぶ引数を使わず)、操作ごとにコマンドを分ける (例: `/dict-add`、`/dict-remove`)。一覧の表示は `-list` で揃える。

例外として、サーバー単位の読み上げ設定 (`/server-set`) は、項目ごとにコマンドを分けると数が多くなるため、1 つのコマンドで項目を選ぶ形とする。項目は Discord の選択肢から選ぶ。

## 9. データ要件

### 9.1 保存先の原則

| 区分 | 保存先 | 例 |
| --- | --- | --- |
| Bot 全体に共通する設定 (運用者が管理する) | JSON ファイル | 対象サーバー (`server_id.json`)、グローバル辞書 |
| サーバーごとのデータ | DB | サーバー辞書、サーバー単位の読み上げ設定 |
| 音声ファイル | ファイルシステム (企画書 5.3) | 音声辞書の音声 |

- 対象サーバーは `server_id.json` を正とする。サーバーごとのデータとの関係を DB 上で扱うため、`server_id.json` の内容を DB にも反映し、DB 側は `server_id.json` に従う。`server_id.json` から外したサーバーのデータは原則として削除せずに残し、DB 側でそのサーバーを無効として扱う (有効かどうかを示す列 (`is_enable` 等) を設ける)。配列に戻した場合は、残っているデータをそのまま使う
- 利用者に返す・利用者から受け取るファイル (サーバー辞書の表示 F-015、一括登録 F-016、声の設定の出力・インポート F-025) は JSON 形式とするが、データ自体は DB に保存する。返すときは DB から取得して JSON 形式に変換し、受け取ったときは JSON の内容を DB に登録する

### 9.2 データ一覧

| ID | データ名 | 内容 | 保存先 | 関係する機能 |
| --- | --- | --- | --- | --- |
| D-001 | 対象サーバー | 対象サーバーのサーバー ID の配列。DB 側では、外したサーバーも無効として残す | `server_id.json` (正)、DB (`server_id.json` に従う) | F-001 |
| D-002 | 利用者の声の設定 | サーバーごと・利用者ごとの声・速度・ピッチ | DB | F-012、F-013、F-025 |
| D-003 | 声の上書き | サーバーごと・メンバーごとの声・速度・ピッチの上書き | DB | F-014 |
| D-004 | サーバー辞書 | サーバーごとの単語と読み (正規表現の単語を含む)、登録者のユーザー ID と登録時のサーバーのニックネーム | DB | F-015〜F-017 |
| D-005 | 音声辞書 | サーバーごとの単語、音声ファイルの保存パス、登録者のユーザー ID と登録時のサーバーのニックネーム | DB (音声ファイルはファイルシステム) | F-018 |
| D-006 | グローバル辞書 | 対象サーバーすべてに適用する単語と読み (正規表現・音声辞書を含む) | JSON ファイル (音声ファイルはファイルシステム) | F-019 |
| D-007 | 読み上げミュート | サーバーごとの、ミュートしたメンバー | DB | F-020 |
| D-008 | 使わせない声 | サーバーごとの、使わせない声 | DB | F-021 |
| D-009 | サーバー単位の読み上げ設定 | 自動接続先を含む、F-023 の各項目 | DB | F-006、F-023 |
| D-010 | 復帰用の接続状態 | 停止時に接続していた VC と、読み上げ対象のテキストチャンネル | Q-010 | F-024 |

Voice Override Mode (F-022) の設定は、VC の接続ごとにメモリ上でのみ持ち、保存しない。

### 9.3 データ取り扱い上の注意

| 項目 | 注意点 |
| --- | --- |
| 発言の本文 | 読み上げのためにのみ扱い、保存しない。ログにも残さない (エラーの種類・サーバー ID など、本文を含まない情報のみを残す) |
| 合成した音声 | 再生のためにのみ扱い、再生が終わったら残さない |
| ユーザー ID・サーバー ID | 設定・ミュート・辞書の登録者とひもづけるために保存する |
| サーバー辞書・音声辞書 | サーバーの全員で共有するデータとして扱う (一般利用者が表示できる)。荒らしへの対処のため、サーバー辞書も音声辞書と同じく、登録者のユーザー ID と登録したときのサーバーのニックネームを保存する (13 章 R-006) |
| 音声辞書の音声ファイル | 権利 (他人の声、著作物など) を本システムで確認することはできないため、登録した投稿者の責任とする。そのため、投稿者のユーザー ID と、登録したときのサーバーのニックネームを保存し、一覧の表示 (F-018) でも誰が登録したものかが分かるようにする |
| 使われなくなったデータ | サーバーを抜けた利用者の設定なども、原則として削除せずに残す。`server_id.json` から外したサーバーのデータも同様 (9.1) |
| 秘密情報・環境ごとの設定 | Git の管理対象外とする (3.3) |

## 10. 音声合成要件

### 10.1 音声 ID の体系

音声 ID の体系は、既存 Bot と同じとする (既存 Bot 仕様書 3.2)。既存 Bot で声の番号を覚えている利用者が、同じ番号で設定できるようにするためである。

| 音声 ID | エンジン |
| --- | --- |
| 0〜999 | VOICEVOX |
| 1000〜1999 | COEIROINK |
| 2000〜2999 | SHAREVOX |
| 3000〜3999 | A.I.VOICE |
| 4000〜4999 | AquesTalk |
| 5000〜5999 | Aivis |

- 用意するエンジンと話者は、別途「利用可能話者一覧」(仮称) で定める
- 用意できないエンジンの範囲は欠番とし、その範囲の ID は存在しない声として扱う
- 6000 以上の ID は欠番とする。既存 Bot は、一覧にない 6000 以上の ID を COEIROINK に送っていた
- 起動時に、各エンジンから話者の一覧を取得して、声の一覧を作る。つながらないエンジンは、どのエンジンでも一覧から外し、ログに出す。既存 Bot は、VOICEVOX につながらない場合に一覧を作れなかった

### 10.2 既存 Bot から修正する点

| 既存 Bot の動作 | 本システムでの扱い |
| --- | --- |
| 声の ID は 4 文字までしか保存できない (企画書 P-003) | 長さに制限のない形で保存する |
| 本文に `_` が含まれると、それ以降が欠落する (企画書 P-007) | 本文が欠けない形でエンジンに渡す |
| 設定の読み出しに失敗すると、ID 0 の声になる (既存 Bot 仕様書 6.3) | DB につながらない場合は停止する (11.2) |
| 全体の接続数が 1500 以上になると、VOICEVOX の声を ID 3 に切り替える (既存 Bot 仕様書 6.3) | 設けない (5.2) |

### 10.3 既存 Bot から引き継ぐ点

| 項目 | 内容 |
| --- | --- |
| Aivis のモデルの登録 | 声の指定 (F-012) に Aivis のモデル UUID を指定すると、そのモデルをエンジンに登録し、声の一覧を作り直す (既存 Bot 仕様書 3.2) |
| 声の利用条件の表示 | 声を設定したときに、エンジンごとの利用条件を表示する。A.I.VOICE は「録音・配信での利用はできない」、AquesTalk は「録音した音声を商用利用する場合は使用ライセンスが必要」(既存 Bot 仕様書 3.2) |

## 11. 非機能要件

### 11.1 性能要件

| 項目 | 要件 |
| --- | --- |
| 読み上げの応答 | 発言から読み上げの開始まで、通常の利用に支障がない時間であること (目安: 3 秒以内)。キューに待機中の読み上げがない状態で、読み上げ文字数の上限 (F-011) 以内の発言について測る |
| キュー | 1 サーバーあたり 30 件までをためられること (F-004) |
| 同時利用 | 対象サーバーそれぞれで、同時に 1 つの VC で読み上げられること |

### 11.2 可用性要件

| 項目 | 要件 |
| --- | --- |
| 読み上げの失敗 | 1 件の合成・再生に失敗しても、その件を飛ばして次の件の読み上げを続けること |
| エンジンの障害 | 一部のエンジンが使えなくても、ほかのエンジンの声は使えること (10.1) |
| DB の障害 | DB につながらない場合は、ログにエラーを出して Bot を停止すること。設定を読めないまま稼働を続けると、さまざまな不具合の要因になるため。停止する前に、接続中の各サーバーの読み上げ対象のテキストチャンネルへ、DB の障害で停止する旨 (再起動の予告ではない) を、設定に関係なく必ず送ること。停止したあとは、原則として自動では起動し直さないこと |
| 再起動 | 再起動のあとも、停止前の読み上げを続けられること (F-024) |

### 11.3 セキュリティ要件

| 項目 | 要件 |
| --- | --- |
| 利用範囲 | 対象サーバーでのみ動作すること (F-001) |
| 権限 | サーバー管理者向けの操作は、Discord の「管理者」権限を持つメンバーのみが実行できること (4.1) |
| 入力値の検証 | 利用者の入力 (単語・読み・数値・ファイル) は Bot 側で検証すること。ファイルは拡張子ではなく中身で判定すること (F-016、F-018、F-025) |
| 正規表現 | 処理時間が入力の長さに比例する方式に限り、重い正規表現による停止を防ぐこと (F-017) |
| 秘密情報 | Bot トークン等をリポジトリに含めないこと (3.3) |
| データの整合性 | DB に主キー・一意制約を設け、同じデータの重複を防ぐこと。確認と更新は 1 つの原子的な操作とすること (企画書 P-002) |

### 11.4 監査性要件

| 項目 | 要件 |
| --- | --- |
| エラーの記録 | エラー、外部サービス (Discord・エンジン・DB) との連携の失敗を確認できること |
| 記録しない内容 | 発言の本文、Bot トークン等の秘密情報をログに含めないこと (9.3) |
| 保管期間 | 昨今のサイバー攻撃の情勢等を考慮し、運用者が定める |

### 11.5 保守性要件

| 項目 | 要件 |
| --- | --- |
| 責務の分離 | 責務ごとにクラス・モジュールを分け、1 つのファイルに責務を集中させないこと (企画書 5.1、P-008) |
| 状態の管理 | 状態の持ち主を明確にし、グローバル変数と別の場所での状態の重複を避けること (企画書 P-009、設計メモ 5.1) |
| テスト | 企画書 3.3 で確認した種類の問題を、単体テスト・回帰テストで予防できること (企画書 G-002) |
| 開発ルール | ブランチ運用は開発ルール (`docs/開発ルール/ブランチ運用ルール.md`) に従うこと |

## 12. 受け入れ条件

本章の条件は、びすこーど！で既存 Bot から本システムに切り替えるときと、正式リリース (企画書 5.4、Q-006) を判断するときの基準とする。

| ID | 条件 | 判定方法 |
| --- | --- | --- |
| A-001 | 機能要件 (F-001〜F-025) が、機能詳細のとおりに動作する | 動作確認 |
| A-002 | `server_id.json` にないサーバーでは、読み上げ等の動作をせず、コマンドにエラーを返す (F-001) | 動作確認 |
| A-003 | サーバー管理者向けの操作を、「管理者」権限を持たないメンバーが実行できない | 権限確認 |
| A-004 | キュー (30 件)、読み上げ文字数 (50〜200 文字)、辞書 (2000 件)、音声辞書 (50 件・10 MiB・10 秒)、読み上げミュート (50 人) などの上限・範囲が守られる | 境界値の確認 |
| A-005 | 企画書 3.3 で確認した種類の問題が起きないことを、回帰テストで確認できる | 回帰テスト |
| A-006 | 発言の本文と秘密情報が、ログに含まれない | ログ確認 |
| A-007 | DB につながらない場合に、DB の障害で停止する旨を通知してから停止し、自動では起動し直さない (11.2) | 障害を想定した確認 |
| A-008 | 一部のエンジンが使えなくても、ほかのエンジンの声で読み上げを続けられる | 障害を想定した確認 |
| A-009 | 再起動のあとに、停止前に接続していた VC (Bot 以外のメンバーがいるもの) へ接続し直す (F-024) | 動作確認 |
| A-010 | キューに待機中の読み上げがない状態で、読み上げ文字数の上限 (F-011) 以内の発言について、発言から読み上げの開始まで、目安 3 秒以内である (11.1) | 計測 |
| A-011 | スマートフォンから、コマンドを操作できる | 実機での確認 |
| A-012 | 問題が起きたときに、原因を確認できる記録 (エラー、外部サービスとの連携の失敗) が残る (11.4) | ログ確認 |

## 13. リスク・懸念点

| ID | リスク | 影響 | 対応方針 |
| --- | --- | --- | --- |
| R-001 | 機能の範囲が広がりすぎる | 完成が遅れる | 対象外 (5.2) を明確にし、機能の追加は要件定義書の改訂として判断する |
| R-002 | 開発者が実質 1 人である | 作業とレビューが偏り、見落としが出る | `main` へのマージに PR と承認を必須とする (ブランチ運用ルール) |
| R-003 | 音声合成エンジンのライセンス・利用規約に反する | 利用の停止、権利者とのトラブル | 用意するエンジンと話者を利用可能話者一覧 (仮称) で確認し、利用条件を表示する (10.3) |
| R-004 | 音声辞書に、権利を侵害する音声が登録される | 権利者とのトラブル | 登録した投稿者の責任とし、登録者を記録・表示する (9.3) |
| R-005 | 荒らし (大量の投稿など) で読み上げが妨げられる | ほかの利用者が読み上げを使えない | キューの上限 (F-004)、`/skip-all` (F-005)、読み上げミュート (F-020) で対処する |
| R-006 | サーバー辞書が荒らされる (不適切な読みの登録・削除) | 読み上げの内容が乱れる | 登録者のユーザー ID とニックネームを記録して一覧で分かるようにする (F-015)。荒らした利用者が辞書のコマンドを使えないようにするには、サーバー管理者が Discord のコマンドの権限設定 (サーバー設定の「連携サービス」から、コマンドごとに使えるメンバーを設定する機能。出典: [Discord Developer Documentation「Application Commands」](https://docs.discord.com/developers/interactions/application-commands)、2026-10-20 確認) を使う。読み上げミュート (F-020) は読み上げのみを止め、コマンドの利用は止めない |
| R-007 | Discord の API や、使うライブラリの仕様が変わる | Bot が動かなくなる | 依存するライブラリのバージョンを固定し、更新は確認してから行う |
| R-008 | GPU を使わないため、合成に時間がかかる | 読み上げの開始が遅れる | 用意するエンジンを、CPU で目安の時間 (11.1) に収まるものに絞る |
| R-009 | DB の障害で Bot が停止する | その間、読み上げを使えない | 停止前の通知とログで気づけるようにし、運用者が復旧する (11.2) |
| R-010 | リポジトリが Public のため、秘密情報が漏れる | Bot の乗っ取りなど | 秘密情報・環境ごとの設定を Git の管理対象外とする (3.3) |
| R-011 | 既存 Bot からの切り替えで、利用者が戸惑う | 使われなくなる | 音声 ID の体系を既存 Bot と同じにし (10.1)、辞書を一括登録で引き継げるようにする (F-016) |
| R-012 | Voice Override Mode (F-022) が、既存 Bot と同じように聞こえない | 要望に応えられない | 既存 Bot の動作は Lavalink 側の反映のタイミングが未確認のため (既存 Bot 仕様書 7.3)、実装時に確認する |
